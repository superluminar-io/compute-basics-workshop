## Launch an EC2 instance

### 📝 Task

Launch an nginx EC2 instance into any private isolated subnet created in the first lab.

### 🔎 Hints

- [What is EC2?](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/concepts.html)
- [EC2 CDK documentation](https://docs.aws.amazon.com/cdk/api/v2/docs/aws-cdk-lib.aws_ec2-readme.html)
- [Amazon Machine Images](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AMIs.html)
- You can build this on top of the first lab's code

### 🗺  Step-by-Step Guide

1. Open
   ```bash
   workshop/workshop_stack.py
   ```

1. Assign the VPC to a variable
   ```python
   vpc = ec2.Vpc(
       self,
       "WorkshopVPC",
       max_azs=2,
       ...
   ```
1. Now launch a t2.micro instance with the Amazon Machine Image (AMI)
   `bitnami-nginx-1.23.3-22-r21-linux-debian-11-x86_64-hvm-ebs-nami` in an isolated subnet:
   ```python
   nginx_instance = ec2.Instance(
       self,
       "NginxInstance",
       instance_type=ec2.InstanceType("t2.micro"),
       machine_image=ec2.MachineImage().lookup(
           name="bitnami-nginx-1.23.3-22-r21-linux-debian-11-x86_64-hvm-ebs-nami",  # noqa: E501
       ),
       vpc=vpc,
       vpc_subnets=ec2.SubnetSelection(
           subnet_type=ec2.SubnetType.PRIVATE_ISOLATED,
       ),
   )
   ```

1. Deploy the project via
   ```bash
   npx cdk deploy
   ```

## Using a Load Balancer

### 📝 Task
Allow the web server to be reached from the internet.

### 🔎 Hints
- [Application Load Balancer (ALB)](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html)
- [CDK ALB](https://docs.aws.amazon.com/cdk/api/v2/python/aws_cdk.aws_elasticloadbalancingv2/README.html)
- [CDK ALB Targets](https://docs.aws.amazon.com/cdk/api/v2/python/aws_cdk.aws_elasticloadbalancingv2_targets.html)

### 🗺 Step-by-Step Guide
1. Open
   ```bash
   workshop/workshop_stack.py
   ```

1. Import `aws_elasticloadbalancingv2`:
   ```python
   from aws_cdk import (
      Stack,
      aws_ec2 as ec2,
      aws_elasticloadbalancingv2 as elbv2,
   )
   ```

1. Instantiate an internet facing load balancer:
   ```python
   alb = elbv2.ApplicationLoadBalancer(
       self,
       "WorkshopALB",
       vpc=vpc,
       internet_facing=True,
   )
   ```
1. Since we configured the ALB to be internet facing, we need to create a public subnet in our existing VPC.
   ```python
   # vpc = ec2.Vpc(…
   #    subnet_configuration=[
   #        …,
            ec2.SubnetConfiguration(
                name="Public",
                subnet_type=ec2.SubnetType.PUBLIC,
                cidr_mask=20
            )
   #    ]
   ```

1. And create a listener:
   ```python
   listener = alb.add_listener(
       "WorkshopListener",
       port=80,
       open=True,
   )
   ```

1. Now we need to add a target, where the traffic from the listener should go:
   ```python
   nginx_target = targets.InstanceTarget(
       nginx_instance,
       port=80,
   )
   ```
   and then register it to the listener:
   ```python
   listener.add_targets(
       "WorkshopTarget",
       port=80,
       targets=[nginx_target],
   )
   ```

1. You can deploy now. Then go to the [load balancers in the EC2 console](
   https://eu-west-1.console.aws.amazon.com/ec2/home?#LoadBalancers:) and have a
   look at what you deployed. Here you can also find the load balancer's DNS name.
   Open this link in your browser and you will find that after some time a gateway
   timeout occurs. Can you find out why?

## Autoscaling

### 📝 Task

Use an Autoscaling Group (ASG) for creating the instance(s).

### 🔎 Hints
- [EC2 Autoscaling](https://docs.aws.amazon.com/autoscaling/ec2/userguide/what-is-amazon-ec2-auto-scaling.html)
- [CDK Autoscaling](https://docs.aws.amazon.com/cdk/api/v2/docs/aws-cdk-lib.aws_autoscaling.AutoScalingGroup.html#allowalloutbound)

### 🗺 Step-by-Step Guide
1. Open
   ```bash
   workshop/workshop_stack.py
   ```

1. Import `aws_autoscaling`:
   ```python
   from aws_cdk import (
      Stack,
      aws_autoscaling as autoscaling,
      aws_ec2 as ec2,
      aws_elasticloadbalancingv2 as elbv2,
   )
   ```

1. Replace the Instance with an Autoscaling Group:
   ```python
   nginx_autscaling_group = autoscaling.AutoScalingGroup(
       self,
       "WorkshopASG",
       vpc=vpc,
       vpc_subnets=ec2.SubnetSelection(
           subnet_type=ec2.SubnetType.PRIVATE_ISOLATED,
       ),
       allow_all_outbound=False,
       instance_type=ec2.InstanceType("t2.micro"),
       machine_image=ec2.MachineImage().lookup(
           name="bitnami-nginx-1.23.3-22-r21-linux-debian-11-x86_64-hvm-ebs-nami",  # noqa: E501
       ),
       min_capacity=1,
       max_capacity=2,
   )
   ```
1. Replace the target group with the following:
   ```python
   nginx_target = targets.InstanceTarget(
      nginx_instance,
      port=80,
   )
   listener.add_targets(
      "WorkshopTarget",
      port=80,
      targets=[nginx_target],
   )
   ```

1. Deploy your changes via
   ```bash
   npx cdk deploy
   ```

## Improving the ASG

### 📝 Task

Use the load balancer's health check for the Autoscaling Group.

### 🔎 Hints

- [Add health check for ASG](https://docs.aws.amazon.com/autoscaling/ec2/userguide/as-add-elb-healthcheck.html)
- [CDK ASG health check](https://docs.aws.amazon.com/cdk/api/v2/docs/aws-cdk-lib.aws_autoscaling.HealthCheck.html#static-elboptions)

### 🗺 Step-by-Step Guide

1. Open
   ```bash
   workshop/workshop_stack.py
   ```

1. Import `Duration`:
   ```python
   from aws_cdk import (
      Duration,
      Stack,
      aws_autoscaling as autoscaling,
      aws_ec2 as ec2,
      aws_elasticloadbalancingv2 as elbv2,
   )
   ```

1. Find your Autoscaling Group and add the following as a property:
   ```python
   health_check=autoscaling.HealthCheck.elb(
       grace=Duration.seconds(60),
   ),
   ```

   Your Autoscaling Group should now look like this:
   ```python
   nginx_autscaling_group = autoscaling.AutoScalingGroup(
       self,
       "WorkshopASG",
       vpc=vpc,
       vpc_subnets=ec2.SubnetSelection(
           subnet_type=ec2.SubnetType.PRIVATE_ISOLATED,
       ),
       allow_all_outbound=False,
       instance_type=ec2.InstanceType("t2.micro"),
       machine_image=ec2.MachineImage().lookup(
           name="bitnami-nginx-1.23.3-22-r21-linux-debian-11-x86_64-hvm-ebs-nami",  # noqa: E501
       ),
       min_capacity=1,
       max_capacity=2,
       health_check=autoscaling.HealthCheck.elb(
           grace=Duration.seconds(60),
       ),
   )
   ```

1. Deploy your changes via
   ```bash
   npx cdk deploy
   ```

1. Terminate the instance from the web console and observe what happens.


## Connect to instance via AWS Systems Manager (SSM) Session Manager

The preferred way to connect to an EC2 instance is using the AWS SSM Session Manager.

### 📝 Task

Launch a plain Amazon Linux 2 instance and connect via AWS SSM Session Manager

### 🔎 Hints

- [AWS SSM Session Manager](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager.html)
- [Deeper integration of Session Manager into you terminal](https://superluminar.io/2023/02/03/ssm-session-manager-no-bastion-host-necessary/)
- [AWS Private Link (Endpoints)](https://docs.aws.amazon.com/vpc/latest/privatelink/what-is-privatelink.html)
- [EC2 instance profiles (roles for instances)](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_switch-role-ec2_instance-profiles.html)

### 🗺 Step-by-Step Guide
1. Open 
   ```bash
   workshop/workshop_stack.py
   ```

1. Add interface endpoints to your vpc:
   ```python
   vpc.add_interface_endpoint(
       "WorkshopSSMEndpoint",
       service=ec2.InterfaceVpcEndpointAwsService.SSM,
   )
   vpc.add_interface_endpoint(
       "WorkshopSSMMessageEndpoint",
       service=ec2.InterfaceVpcEndpointAwsService.SSM_MESSAGES,
   )
   vpc.add_interface_endpoint(
       "WorkshopEC2MessageEndpoint",
       service=ec2.InterfaceVpcEndpointAwsService.EC2_MESSAGES,
   )
   ```

1. Import `aws_iam` into your module:
   ```python
   from aws_cdk import (
       Stack,
       aws_ec2 as ec2,
       aws_elasticloadbalancingv2 as elbv2,
       aws_elasticloadbalancingv2_targets as targets,
       aws_iam as iam,
   )
   ```

1. Create a new iam role with the AWS Managed Policy `service-role/AmazonEC2RoleforSSM` attached. Make the role assumable by the EC2 service
   principal (`ec2.amazonaws.com`):
   ```python
   instance_role = iam.Role(
       self,
       "WorkshopInstanceRole",
       assumed_by=iam.ServicePrincipal("ec2.amazonaws.com"),
       managed_policies=[
           iam.ManagedPolicy.from_aws_managed_policy_name(
               "service-role/AmazonEC2RoleforSSM"
           ),
       ],
   )
   ```

1. and create a new instance with this role attached:
   ```python
   ec2.Instance(
       self,
       "WorkshopInstance",
       instance_type=ec2.InstanceType("t2.micro"),
       machine_image=ec2.MachineImage.latest_amazon_linux2(),
       vpc=vpc,
       vpc_subnets=ec2.SubnetSelection(
           subnet_type=ec2.SubnetType.PRIVATE_ISOLATED,
       ),
       role=instance_role,
   )
   ```
   Note: we need a new instance, as the bitnami nginx image does not come with the SSM agent installed. This can be done, however, using
   e.g., [user data](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/user-data.html) or via direct login from ssh. In both cases, it is
   absolutely recommended to create an AMI from the machine after installation and continue using this AMI in operations.

1. Deploy your changes and go to the [SSM Session Manager](https://eu-west-1.console.aws.amazon.com/systems-manager/session-manager/sessions).
   Click on "Start session", select your EC2 instance and click "Start session" again. A new ssh terminal will open in your browser. If you
   prefer using your terminal, check out [this blog post](https://superluminar.io/2023/02/03/ssm-session-manager-no-bastion-host-necessary/).
