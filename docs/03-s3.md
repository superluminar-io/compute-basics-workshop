## Create an Amazon S3 Bucket

### 📝 Task

Create an S3 Bucket with versioning and create a gateway endpoint

### 🔎 Hints

- [What is S3?](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html)
- [S3 CDK documentation](https://docs.aws.amazon.com/cdk/api/v2/python/aws_cdk.aws_s3/Bucket.html)
- You can build this on top of the last part of the second lab's code.

### 🗺  Step-by-Step Guide

1. Open
   ```bash
   workshop/workshop_stack.py
   ```
   and (optionally) remove the Auto Scaling group and the load balancer, including all related permission setups.

1. Import `aws_s3`:
   ```python
   from aws_cdk import (
       Stack,
       aws_ec2 as ec2,
       # maybe you have load balancer import here, if you didn't remove it
       aws_iam as iam,
       aws_s3 as s3,
   )
   ```

1. Create an S3 Bucket with versioning and encryption enabled:
   ```python
   s3_bucket = s3.Bucket(
       self,
       "WorkshopBucket",
       block_public_access=s3.BlockPublicAccess.BLOCK_ALL,
       encryption=s3.BucketEncryption.S3_MANAGED,
       versioned=True,
   )
   ```
1. For convenience reasons, we also add the bucket name, which is auto-generated, as an output. With your next deployment
   you will have the bucket name printed to the console. Add `CfnOutput` to your imports:
   ```python
   from aws_cdk import (
       CfnOutput,
       Stack,
       aws_ec2 as ec2,
       aws_iam as iam,
       aws_s3 as s3,
   )
   ```

1. Below your bucket construct add:
   ```python
   CfnOutput(
       self,
       "WorkshopBucketName",
       value=s3_bucket.bucket_name,
   )
   ```

1. Deploy the project via
   ```bash
   npx cdk deploy
   ```
   and check the output for your bucket.

1. Use AWS SSM to connect to your instance again. On the machine, run
   ```bash
   aws s3api list-buckets --region eu-west-1
   ```

## Adding an S3 endpoint

## Using Instance Profiles

### 📝 Task

Attach policies to the instance profile to allow S3 to be accessed from your EC2 instance.

### 🔎 Hints
- [What are instance profiles?](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_switch-role-ec2_instance-profiles.html)

### 🗺 Step-by-Step Guide
1. Open
   ```bash
   workshop/workshop_stack.py
   ```

1. Add a policy to allow listing all buckets:
   ```python
   instance_role.add_to_policy(
       iam.PolicyStatement(
           actions=[
               "s3:ListAllMyBuckets",
           ],
           resources=[
               "*",
           ],
       )
   )
   ```
   In production you will most likely not need this permission and it is a bit unhandy to use.

1. Deploy your changes and try listing your buckets from the EC2 instance again. This time you will get a list of all buckets in the
   account.

1. Just listing the bucket will not be enough for most applications. You can also try putting a file into your bucket.
   Switch to the home folder with `cd`. Create a file on your EC2 instance using any installed editor (tested vim and nano). Now upload
   the file to S3:
   ```bash
   aws s3api put-object --bucket <your bucket> --key <file name in the bucket> --body <local file name> --region eu-west-1 
   ```
   There also is a more high level api you can use:
   ```bash
   aws s3 cp <local file name> s3://<your bucket>/<file name in the bucket> --region eu-west-1 
   ```
   The result will be permission denied again. We still need to grant the instance permissions to read and write objects in the bucket.

1. The solution is to add another policy statement to the instance role. For this, assign the bucket to a variable and grant the role of
   the instance profile access to the S3 Bucket:
   ```python
   s3_bucket.grant_read_write(instance_role)
   ```
   This is also the preferred way to manage IAM permissions in CDK, as this grants the minimal permissions necessary to read and write exactly
   this bucket and nothing else (least priviledge)

1. Deploy your changes via
   ```bash
   npx cdk deploy
   ```
   and upload your file now. You can now check in the web console that your file has indeed been uploaded.


## Playing with Versioning

### 📝 Task

Delete and restore your object using bucket versioning.

### 🔎 Hints
- [What is object versioning?](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html)

### 🗺 Step-by-Step Guide

1. Go to the [S3 console](https://s3.console.aws.amazon.com/s3/buckets) and select your bucket. Find the file you just overwrote and select it.

1. You will now see several properties of the file like the file ARN, its S3 URI (which you need for the high level aws cli s3 api), or an
   object URL, which you would use to access the object via HTTPs. Since the bucket is not public, you will not be able to use this, though.
   Also, there is a tab called "Versions" at the top. Click this to inspect all version of the given object. This feature can be very useful
   to prevent files from being deleted accidentally.

1. Now lets try this out. Go back to your bucket objects overview. Select your test object and delete it. You will be prompted to confirm the
   deletion and you have to enter *delete*. If the console prompts you to enter *permanently delete* there ist something *wrong*.

1. Now find the "Show versions" toggle next to the search bar and enable it. You will see, your object is
   not gone but instead a delete marker has been created. To restore your object, you can select the delete marker and delete it 🤪.
   This time you will be prompted to confirm with *permanently delete*. As a rule of thumb: if you delete a version of an object, it is gone for
   good, therefore you should only do this if absolutely necessary (e.g., when you need to clean up a bucket completely before deleting it).

1. Switch of the "Show versions" toggle and your file should re-appear.
